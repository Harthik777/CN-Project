# Recorded network datasets

The [public packet lab](https://harthik777.github.io/CN-Project/#packets) includes six payload-redacted excerpts from two public Stratosphere Laboratory captures. Select a **Bundled dataset** and choose **Analyze selected dataset**. The PCAP bytes and trained model are embedded in the page, so analysis and downloads work in browser-only mode without Render or the dataset publisher being reachable.

## Source data

| Source | Recorded traffic | Full source size | Packaged excerpts |
|---|---|---:|---:|
| [CTU Normal 4](https://mcfp.felk.cvut.cz/publicDatasets/CTU-Normal-4-only-DNS/) | DNS traffic from a normal computer, recorded in March 2015 | 772,961 bytes | Beginning, midpoint, end |
| [CTU-13 scenario 7](https://www.stratosphereips.org/datasets-ctu13) | Traffic captured from the infected virtual machine in the August 2011 Sogou experiment | 18,868,213 bytes | Beginning, midpoint, end |

These are recordings from external networks/experiments, not packets generated by this project's teaching-data script. The botnet scenario is a controlled research experiment, not representative production traffic. The normal capture contains DNS only because the publisher removed other traffic for privacy.

Source URLs, file sizes, full SHA-256 values, source packet numbers, derived excerpt hashes, citations and summaries are in [manifest.json](../artifacts/real_captures/manifest.json). Packet reports identify their source by the analyzed file's hash, so changing the dataset selector cannot mislabel a previously displayed result. JSON exports include that source record and the transformation description.

## Reproducible preparation

`scripts/prepare_real_captures.py` downloads only the two PCAP files when `--download` is specified. It checks their pinned hashes and sizes before preparing data. Normal use, CI and the demo use the packaged artifacts and need no external dataset download.

1. Read every source PCAP record and retain complete supported TCP/UDP packets. The DNS source has 5,966 supported packets; the botnet source has 20,604 supported packets, with 49 non-IP records and 10 other-IP-protocol records excluded.
2. Take 200 supported packets from the beginning, around the midpoint and at the end of each source's supported-packet sequence. Windows are disjoint. Selection is fixed before scoring and does not depend on model scores or labels.
3. Replace application payload contents and Ethernet padding with zero bytes and recompute TCP/UDP checksums. Preserve addresses, timestamps, packet lengths, flags, sequence/acknowledgement fields and TCP options. The resulting files are explicitly labeled as modified excerpts.
4. Compare each excerpt before and after redaction using the frozen model. All extracted flow fields, features, scores and flags must match exactly. Store source and derived hashes separately.

```powershell
python -m pip install -r requirements-api.txt -r requirements-dev.txt
python scripts/prepare_real_captures.py --download
python -m unittest discover -s tests -p test_real_captures.py -v
python scripts/verify_browser_packets.py
```

Each excerpt fits the existing 512 KiB / 6,000-packet / 250-flow limits. The total addition is **1,200 packets and 194 extracted flows**. Excerpts can start or end mid-conversation; their flow statistics describe only the included packets. Payload removal preserves the current header/length features but makes the downloads unsuitable for DNS-name, application-content or malware-payload inspection.

## Frozen-model transfer result

| Source context | Excerpts | Packets | Extracted flows | Flagged | Flagged fraction |
|---|---:|---:|---:|---:|---:|
| Normal DNS | 3 | 600 | 159 | 153 | 96.2% |
| Botnet-host capture | 3 | 600 | 35 | 32 | 91.4% |

**The synthetic-trained model transfers poorly to normal DNS traffic.** It flags almost all normal DNS flows in these excerpts. A high botnet-host flag fraction therefore does not establish useful attack discrimination. These results are reported to expose the domain mismatch, not to claim successful real-world attack detection.

The original Isolation Forest and validation threshold are unchanged. These sources were not used for training, calibration or selection of a favorable threshold. The original synthetic precision/recall table still describes the original synthetic test split only.

The CTU-13 publisher provides Argus bidirectional-flow labels with different aggregation boundaries. The botnet VM capture and router-level labeled flow file also represent different capture points. No verified join to the bounded excerpts was performed. Capture-level context therefore does not become a binary ground-truth label for each extracted flow, and this release reports **no real-data accuracy, precision or recall**. A later model study would require suitable real benign training traffic, separate calibration/test captures and a validated label mapping.

## Correctness evidence

Four data tests verify packaged hashes and disjoint source-record selection, independent dpkt packet/length accounting, zeroed application payloads and valid transport checksums, redaction invariance, and reproduction of the frozen-model counts above. The Python/browser differential suite now covers **136 captures and 1,244 flows**, including all six real excerpts, with matching flags and maximum score difference `1.1102230246251565e-16`. This is implementation agreement, not an accuracy measure.
